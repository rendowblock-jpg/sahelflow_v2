## 1. Internal.16 is the complete-product candidate

Internal.15 remains the exact FD-032 Founder-only offline checkpoint. Internal.16 is intentionally different: it is built as the first complete SahelFlow application candidate rather than another partial route or subsystem checkpoint.

Internal.16 must converge in one controlled implementation frontier:

- remaining Phase 5 whole-product AAA route adoption;
- remaining Phase 6 Arabic/RTL/accessibility closure;
- remaining Phase 7 performance/reliability implementation and certification;
- full Phase 8 connected-platform implementation;
- delivery-provider cleanup and first-class EcoTrack Pro integration;
- AI workspace, order-extraction and AI-tool correctness/performance hardening;
- release, updater, recovery, licensing, cloud, privacy/security and whole-product verification required for a user-ready candidate.

This changes the implementation sequence for exact Internal.16. It does **not** mark any unfinished Phase 5/6/7/8 gate as passed. Those obligations become integrated Internal.16 acceptance gates and must be objectively satisfied before a user-ready claim.

## 9. Installed Internal.15 Founder Problem Register — Parts 1–3

The following installed observations are binding inputs to the final Internal.16 Problem Register. Discovery remains open until the Founder explicitly closes it.

### SF16-UI-001 — Systemic Arabic/RTL geometry and bidi parity — P1

Installed Arabic proves that physical sidebar placement is not enough: selected/nested rails, icon/text order, panes, tables, actions, charts, menus and mixed content can still express LTR semantics. Internal.16 must define one semantic RTL geometry contract and audit every production UI consumer. The implementation agent owns exhaustive discovery; the Founder is not required to screenshot every occurrence.

Acceptance covers Dashboard, Orders, Risk, Customers, Products, Delivery, Accounting, Analytics, Inbox, AI and Settings; 1366×768; 100–200% zoom; expanded/collapsed sidebar; keyboard; AR↔FR/EN switching; chart axis/legend/tooltip order; and bidi isolation for phones, IDs, currency and mixed text.

### SF16-UI-002 — Risk Engine KPI hierarchy — P1

Six equal-weight risk cards create weak decision hierarchy and orphaned composition. Preserve truthful metrics but redesign primary versus supporting signals so current risk posture, adverse trend and actionable workload are immediately understandable. No visually orphaned partial row is acceptable.

### SF16-UI-003 — Shared stat-card interaction semantics — P1

Shared KPI/stat cards feel inert. Create explicit `passive`, `actionable/drill-down` and true `selected` states. Hover/focus should use bounded theme-aware border/surface/icon feedback; actionable cards must be real accessible links/buttons; passive cards must not fake clickability. Keyboard, touch and reduced-motion parity are required.

### SF16-I18N-004 — Locale-safe money/date/number formatting — P1

Arabic can leak French `DA` when locale-sensitive formatters default to French. Audit all money/date/relative-date/chart formatter calls. Arabic must render `دج`, French `DA`, English `DZD`, with correct bidi/numeral behavior across routes, charts, exports and prints.

### SF16-INBOX-005 — Final AAA Inbox convergence — P1

Inbox is materially improved but still below final AAA. Build an adaptive/resizable queue-thread-context workspace, strong triage hierarchy, useful no-selection state, complete supported message/media/template/extraction/collaboration/workflow behavior, sticky fast composer, local history during degraded WhatsApp transport, safe retry/reconnect, large-history bounded rendering and explicit wide/windowed/narrow layouts. Preserve protected Inbox/provider authorities.

### SF16-AI-006 — Final AAA AI workbench convergence — P1

The current AI workbench is too rigid. Make the thread dominant and session/context rails adaptive/collapsible/resizable with correct RTL order. Complete polished session creation/switching, streaming/stop/retry, composer, tool progress/results, source/record context, proposal review, setup/provider/quota/degraded states and long-session performance. Persisted historic content stays exact; new system/assistant presentation follows active product language unless user context dictates otherwise.

### SF16-I18N-007 — Zero unresolved translation keys or unintended foreign system copy — P1

Installed Settings rendered `auth.pinPlaceholder`; Gemini server/verifier paths contain hard-coded French human messages. Release checks must reject unresolved key-like UI output. Server/provider failures should expose stable codes/metadata and localized UI should own human wording. SahelFlow-owned demo/system content becomes locale-aware; seller-entered shop/product/customer names remain exact and are not silently translated.

### SF16-PRODUCTS-008 — Product-row media identity — P1

Product workbench records already expose `images`; the table omits them. Render a compact primary thumbnail beside the product name with intentional fallback, bounded/lazy loading, low-end-safe decode/cache behavior, appropriate semantics and stable normal/compact RTL/LTR layouts.

### SF16-SEARCH-009 — Universal operational topbar search — P1

Current search is limited to navigation plus bounded orders/customers/products. Internal.16 must provide ranked, shop/permission-aware operational search across approved routes/commands, order identifiers/fields, customer names/phones, product name/SKU/barcode, shipment/tracking references, returns, Inbox conversations, COD/accounting references, automations and other high-value records. Exact numeric identifiers must work naturally. Normalize safe Arabic/French/mixed input, cancel stale requests, deep-link results and stay within Phase 7 search budgets without becoming a protected-field oracle.

### SF16-AI-010 — Gemini key lifecycle is not release-ready — P1

Founder-entered Gemini key did not make AI usable. Do not guess the external cause. Certify:

```text
recent PIN reauthentication
→ localized key entry
→ current official Gemini endpoint/model-policy verification
→ encrypted protected save
→ persisted configured + verified state
→ immediate AI readiness refresh without restart
→ one real minimal assistant/extraction request
→ ongoing provider/quota/model health
```

Distinct localized errors are required for invalid/restricted key, disabled API, unsupported model, quota/rate limit, network/timeout, protected-secret storage, reauth expiry, consent and license blockers. Revalidate current official Gemini authority before implementation; the key may never enter logs/evidence.

### SF16-RESP-011 — Deterministic responsive composition — P1

Shared `auto-fit` layout currently permits four KPI cards to become an ugly `3 + 1` in normal windowed mode. Replace accidental auto-fit composition with item-count/container-aware rules: four primary cards normally `4 → 2×2 → 1`; six-card groups balanced `3×2`/`2×3` or deliberate primary/supporting hierarchy. Validate real application container width after sidebar, live resize, 1366×768, 100–200% zoom, density and AR/FR/EN/RTL.

### SF16-LAYOUT-012 — Eliminate low-information dead space and stretched panels — P1

**Observed:** the Dashboard Delivery panel is stretched to match a taller Recent Orders sibling and leaves a large empty lower region; Risk/Analytics cards also show oversized blank canvas around relatively small chart content.

**Source clue:** the Dashboard places Recent Orders and Delivery in one CSS grid row, whose default stretch behavior equalizes item height while Delivery’s internal metric grid occupies only the top. The governed chart frame also defaults to fixed plot heights even when the visualization uses much less visual area.

**Requirement:** every card/panel must size from information and hierarchy rather than sibling accident. Use `align/self-start`, deliberate equal-height content, adaptive min/max heights or changed composition as appropriate. Chart height, radius, legend and supporting context must adapt to available data and container size. Empty states should be purposeful, not a large blank rectangle. Preserve stable page rhythm without forcing unrelated cards to the same height.

**Acceptance:** no material low-information blank region caused by accidental grid stretch/fixed chart canvas at full/windowed widths, 1366×768, 100–200% zoom, AR/FR/EN/RTL and normal/compact density.

### SF16-CHART-013 — Rebuild analytics/charts into a top-tier decision system — P1

**Observed:** many installed charts look generic, sparse and under-engineered rather than like a premium operational analytics product.

**Source clues:** shared `ChartCard` defaults to a fixed 300px plot; donut geometry uses fixed radii inside that canvas; Analytics passes an `accent` property that the current `ChartCard` does not consume; chart formatters can also fall back to the wrong locale when callers omit it.

**Requirement:** keep one governed chart foundation but redesign it around seller decisions. Each chart must justify its chart type, information density and visual weight; include useful comparison/baseline, period context, selective labels/annotations, rich accessible tooltip, legend where useful, concise summary, drill-down/source-record action where authority supports it, locale-correct units, bidi-safe RTL geometry and accessible text/table equivalent. Use richer but restrained visuals—professional gradients, active states, reference lines/bands, comparative series, segmentation or annotations only when they clarify real data. Do not replace weak charts with decorative complexity.

Charts must adapt height/label density to container width and data volume, remain bounded on T470/floor hardware, respect reduced motion and have stable visual-regression evidence. Analytics, Dashboard, Risk, Delivery, Accounting and future Phase 8 analytics must use the same governed system.

### SF16-PERF-014 — Startup/first-open performance must be measured and improved — P1

**Observed:** installed Internal.15 still feels slow to open, especially the first launch after update.

Do not optimize by guess. Release startup already performs protected recovery checks, all-shop migration/authority preparation, packaged runtime startup/readiness and workspace navigation before showing the real workspace. Internal.16 must instrument and retain stage timings for at least process start, recovery/preflight, device/license authority, migration, runtime preparation/spawn, runtime readiness, first navigation, authenticated hydration and first usable workspace.

Required evidence separates ordinary cold start, first launch after Internal.15→16 update/migration, and warm/reopen behavior. Preserve Phase 7 targets: T470 cold launch ≤8s p95; declared floor usable shell ≤15s p95 SSD / ≤25s HDD. If update-only migration legitimately adds bounded work, report that separately rather than hiding it inside an average. No startup optimization may weaken migration, licensing, containment, recovery or authenticated-readiness guarantees.

### SF16-THEME-015 — Theme switching must be atomic and visually smooth — P1

**Observed:** light/dark switching still glitches for a visible moment before settling.

Current theme authority is centralized, but the installed result proves the broad 220ms appearance-transition window is not sufficient. Internal.16 must make theme/preset switching one atomic appearance transaction: no frame may show mixed old/new surface, text, border, icon, chart, overlay or portal tokens. Pre-hydration, hydrated state, localStorage failure, system theme, all four presets, dialogs/popovers and charts must share the same committed appearance.

Use bounded transitions on properties that benefit from interpolation and avoid transitions that expose intermediate unreadable/incorrect contrast. Target a visually settled switch within the existing short interaction envelope, with no flash/flicker/reflow; reduced-motion switches immediately without animation. Validate repeated rapid switching, windowed/fullscreen, portals and startup/reopen persistence.

### SF16-I18N-016 — Locale switching must be atomic across current and future routes — P1

**Observed:** after changing Arabic→English (and vice versa), the current page may update but navigating to another page can briefly show the previous language before catching up.

The current model writes the locale cookie and refreshes the current Server Component tree. Internal.16 must close the route-cache/prefetch/navigation boundary so a committed locale applies to **every subsequent route immediately**. Once the language selector reports the new locale as committed, no navigation may reveal an old-locale page, sidebar, cached server fragment or portal even for a transient frame.

Requirements: one locale epoch/authority across server requests, client bundle, document `lang/dir`, route cache/prefetch and shell; cancel or invalidate stale prior-locale route data; atomic direction/geometry commit; pending state that remains understandable without partially switching the product; preservation across restart; no full app restart required. Test AR↔FR↔EN on every major route with prefetched and non-prefetched navigation, rapid switching, back/forward and window resize.

### SF16-NAV-017 — Smarter default sidebar order + user reorder control — P1 Founder product requirement

**Observed/requested:** the current page sequence does not feel optimally organized for daily seller work. The Founder wants a small pencil/edit control in the sidebar that allows the seller to customize page order.

The current `navigationDomains` registry remains the canonical route/relationship authority. Internal.16 must not let customization duplicate or mutate permission/route truth. Instead, create a separate presentation-order preference layered over the canonical registry.

**Default order:** re-evaluate the visible order against frequency and Golden COD workflow so the highest-frequency daily work is closest together (dashboard/attention, orders/confirmation, Inbox/customer follow-up, catalog/inventory, fulfillment/returns, money/reconciliation, analytics/automation/AI/storefront, with administration kept distinct). Freeze the exact default after the whole-product route inventory rather than preserving historical order by inertia.

**Edit experience:** small discoverable pencil/edit control in expanded sidebar (and accessible equivalent when collapsed) opens a compact navigation-customization surface. Support drag reorder plus keyboard move up/down, clear current position, save/cancel, reset-to-SahelFlow-default and immediate preview. Preserve genuine nested workflow relationships and keep utility/security destinations appropriately separated. Reordering must not change URLs, permissions, command search, route context or business authority.

Persist the preference best-effort as UI preference scoped appropriately to the local person/workspace; corrupt/stale preferences normalize safely when routes change. Validate RTL/LTR drag/keyboard direction, expanded/collapsed sidebar, zoom, touch/coarse pointer and migration when new pages are introduced.

## 4. First implementation milestone: M0 only

Start with **Milestone M0 — Authority, branch protection and reproducible verification**. Do not jump directly to cloud, PWA, storefront, teams, licensing UI or visible page work.

The unified vision does not change the dependency order. It ensures every safe foundation ultimately delivers the complete product and experience.

### M0-0 — Vision recovery and traceability

Completed by the unified vision package. Before merge, review that:

- final founder decisions are unchanged;
- durable historical requirements are preserved;
- obsolete assumptions are clearly superseded;
- all capability groups map to milestones;
- UI/UX is a horizontal track rather than hidden only in M13.

### M0-1 — Operational CI diagnosis and repair

- Determine why GitHub Actions jobs fail before any step.
- Restore a clean-checkout PR workflow.
- Keep the failure itself as incident/evidence.
- Do not weaken checks to make them green.

### M0-2 — Single version/evidence manifest

- Define the generated authority for app `1.x.y`, product major, commit, build/channel, schema/protocol/projection/backup/storefront versions, compatibility ranges, signing key IDs and artifact digests.
- Make package.json, Cargo, Tauri, About/updater/release metadata derive from or validate against it.
- Plan the safe migration from internal labels to first public SahelFlow 1.0.0.

### M0-3 — Branch protection and workflow templates

- Required checks, risk reviewers, issue/PR templates and merge policy from the Coding Workflow.
- Issue template must include capability, journey, surface, role, states, experience dimensions, founder decision, milestone/invariant and evidence.
- No direct push or release publication from local scripts.

### M0-4 — Generated repository/evidence inventory

- Generate tracked route/API/model/migration/test/provider/version inventories from a clean checkout.
- Add page/surface inventory fields from `TRACEABILITY_MATRIX.md`.
- Store exact commit and scope.
- Add claim-drift checks so manual counts/readiness claims cannot become authority.

### M0-5 — Documentation/evidence gates

- Validate links/authority/status headers.
- Define immutable evidence-record schema and candidate artifact retention.
- Make Evidence Ledger and traceability updates part of implementation completion.

Each issue must satisfy the issue-readiness template and risk rules in `CODING_WORKFLOW.md` before code begins.

## 5. Product and experience obligations that must not be lost

- The Windows desktop is the full canonical product, not a shell around cloud authority.
- Teams, roles, field permissions, assignments, queues and approvals are launch scope.
- The PWA/browser companion is operational, not merely an installable viewer.
- Storefronts use a shared multi-tenant platform, durable checkout and three distinct templates.
- Zero-knowledge backup includes an independent recovery kit and replacement-install restore.
- Products, customers, orders, inventory, delivery, returns, refunds, COD, expenses, analytics, automations, inbox and AI require complete workflows—not isolated CRUD screens.
- Every critical page includes loading, empty, error, offline, degraded, conflict and recovery states as applicable.
- Data UX, audit history, onboarding, accessibility, Arabic/RTL and low-end behavior are first-class requirements.
- Marketing/download/security/support/legal and founder-admin surfaces remain part of the full launch structure.
- Provider existence is not a public support claim; certification governs exposure.

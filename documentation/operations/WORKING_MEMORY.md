## Frozen shared contracts

- The DPAPI-protected installation root is a local KEK/derivation root, not a
  universal seller-data key.
- HKDF-SHA-256 derives versioned, purpose-separated installation keys.
- Shops have independently rotatable data/blind-index descriptors; secrets use a
  separate purpose; backups later use a per-license BRK and random per-backup DEK.
- New protected values use one contextual versioned AEAD envelope; decryption or
  format failure becomes explicit protected-data corruption.
- Backup is one immutable all-shop installation snapshot with an authenticated
  encrypted manifest and complete recovery-set classification.
- Native SQLite Online Backup API snapshots replace unlocked copies of live files.
- Restore follows staged verification, authorization, rescue, all-shop cutover,
  post-apply verification and commit; failure preserves or restores the previous
  generation.
- Replacement installs re-wrap imported shop/secret keys under a new local root
  and do not silently clone or revoke installation/device identity.
- Migration journals are authenticated, exact-identity-bound and restart-safe.
- Every durable object receives purpose, retention, backup/export/deletion and
  diagnostic classification; legal claims require independent review.
- Phase 4 closure requires Level 1 unit/property evidence, Level 2 disposable
  all-shop fault matrices and Level 3 packaged/installed Windows replacement proof.

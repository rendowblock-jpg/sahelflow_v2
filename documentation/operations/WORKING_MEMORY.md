## Consolidated Phase 4 Problem Register

The detailed register, evidence and closure tests live in issue #204. Current root
causes are:

- **P4-001/P4-002 — backup protocol:** active-shop raw file copy, plaintext storage,
  unauthenticated sidecar manifest and no BRK/per-backup DEK;
- **P4-003 — incomplete recovery set:** shop registry, identity/control, protected
  key recovery, licensing/commercial state and transfer policy are not one unit;
- **P4-004 — key-purpose collapse:** the protected installation root is still the
  effective compromise domain for PII, secrets, blind indexes and control MACs;
- **P4-005/P4-006 — crypto format/corruption:** no version/key/purpose/context AAD
  envelope and decryption failures can silently surface raw ciphertext/indexes;
- **P4-007 — authority split:** migration rollback is hardened but not yet the
  authenticated backup/replacement-restore protocol;
- **P4-008 — classification/bypass:** protected-field coverage, JSON payloads,
  audit content, AI/provider data and raw Prisma consumers require one inventory;
- **P4-009 — destructive/privacy lifecycle:** reset, erase, shop deletion, backup
  retention and export are fragmented;
- **P4-010/P4-011 — evidence/security operations:** replacement-install matrix,
  SBOM/VEX, threat model, Law 18-07 mapping and independent reviews remain open;
- **P4-012 — CI consequence mapping:** corrected in PR #206;
- **P4-013 — truth drift:** stale SHAs and pre-Teams/SQLCipher source comments must
  be repaired in their owning packages.

No package may create a competing backup, key, journal or restore authority to work

## Frozen shared contracts

- the DPAPI-protected installation root is a local KEK/derivation root, not the
  universal data key;
- HKDF-SHA-256 derives versioned, purpose-separated installation keys;
- shops have independently rotatable data/blind-index descriptors; secrets have a
  separate wrapping purpose; backups use a per-license BRK and random per-backup DEK;
- new protected values use one versioned AEAD envelope with algorithm/key/purpose
  metadata and canonical workspace/shop/incarnation/model/record/field AAD;
- decryption or format failure becomes an explicit protected-data corruption state;
- backup is one immutable all-shop installation snapshot with an authenticated
  encrypted manifest and complete recovery-set classification;
- native SQLite Online Backup API snapshots replace unlocked copying of live files;
- restore follows staged verification, authorization, rescue, all-shop cutover,
  post-apply verification and commit; any failure leaves or restores the previous
  generation as authority;
- replacement installs re-wrap imported shop/secret keys under a new local root and
  do not silently clone or revoke installation/device identity;
- migration journals are authenticated, exact-identity-bound and restart-safe;
  applying a transform and recording its migration ID cannot diverge silently;
- every durable field/object receives purpose, retention, backup/export/deletion
  and diagnostic classification; legal compliance claims require review of Law
  18-07 as amended by Law 25-11 of 24 July 2025;
- Phase 4 closure requires Level 1 unit/property evidence, Level 2 disposable
  all-shop fault matrices and Level 3 packaged/installed Windows replacement proof.

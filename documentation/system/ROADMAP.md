## Program rule

Phases remain semantic quality/architecture authorities. FD-033 changes only the
execution order for exact Internal.16: remaining Phase 5/6/7 closure and Phase 8
implementation may be performed in one dependency-correct application branch after
Internal.15, with all formerly sequential gates evaluated against the frozen
Internal.16 candidate before a user-ready claim.

The default material-package flow remains:

```text
reconnaissance
→ consolidated Problem Register
→ current research / authoritative provider-platform contracts
→ freeze shared contracts and non-goals
→ coherent implementation
→ focused checks
→ frozen adversarial review
→ consolidated repair
→ exact-head proof
→ merge / release evidence
→ documentation reconciliation
```

For Internal.16 specifically, multiple completion outcomes are intentionally grouped
into one large implementation wave after one whole-product reconnaissance. Expensive
MSI/recovery/eight-hour/whole-release evidence is not repeated after every tiny edit.

## Phase 7 — performance and reliability

**Status:** query/index/measurement infrastructure exists; final installed closure is
an Internal.16 acceptance gate.

### T470 targets

- cold launch ≤ 8 s p95;
- ordinary navigation ≤ 700 ms p95;
- indexed search ≤ 350 ms p95;
- ordinary local mutation ≤ 500 ms p95.

### Declared floor targets

- usable shell ≤ 15 s p95 on entry SSD and ≤ 25 s p95 on HDD;
- input acknowledgement ≤ 100 ms;
- navigation ≤ 1.5 s p95;
- indexed search ≤ 750 ms p95;
- local mutation ≤ 1 s p95;
- no ordinary freeze > 200 ms;
- steady working set ≤ 750 MB with WhatsApp connected;
- no sustained memory growth across the required eight-hour final-candidate run.

### Internal.16 performance scope

Measure startup stages, navigation, data queries, table/chart rendering, locale/theme
switches, AI workspace long sessions, extraction routing, AI tool dispatch/execution,
provider workers, Phase 8 remote/cloud synchronization and sustained resource use.

External/model/provider latency is reported separately from SahelFlow's own overhead so
slow networks cannot hide local inefficiency and local performance budgets do not
pretend to control third-party response time.

## Completion wave C — provider convergence and EcoTrack Pro

Remove NOEST as a supported runtime provider and implement canonical EcoTrack Pro with:

- protected credentials/configuration and connection/capability verification;
- current authoritative endpoints/contracts only;
- shipment creation plus any provider-required validation step;
- supported fulfillment modes, recipient/COD/weight/notes/exchange fields;
- tracking and complete normalized/provider-detail history;
- tariff/reference/location data where supported;
- cancellation/update/re-dispatch/return/document/label operations only when supported;
- timeout/rate/retry/ambiguous-response classification;
- durable reconciliation/idempotency so unknown create/validate outcomes never silently
  duplicate parcels;
- safe compatibility for historical `noest` records without silently reinterpreting
  provider identity or credentials;
- deterministic conformance and truthful live-certification state under FD-030.

## Completion wave D — AI workspace, order extraction and tools

### AI workspace

Enhance and prove session switching/history, streaming, cancel/retry, long-session
rendering, context/action review, mobile/desktop layouts, localized typed tool cards,
setup/key/consent/provider/quota/persistence/degraded states, AR/FR/EN, RTL,
accessibility and low-end responsiveness.

Sensitive actions retain exact persisted proposal/digest/actor/shop/license/permission/
target authority. UI convenience must not create a new execution authority.

### Order extraction

Audit the existing regex/Gemini smart router and metric pipeline. Build a held-out
representative corpus with Arabic, French, English, Algerian Darija and mixed content,
including noisy WhatsApp-style orders, partial/contradictory messages and non-orders.

Retain field-level accuracy, required-field completeness, false-complete rate,
confidence calibration, missing-field truth, route selection, fallback/no-key behavior,
invalid-model-response handling, quota/rate-limit behavior and latency distributions.

Low-confidence or incomplete results require explicit review/repair and never invent
canonical order truth. Extraction remains upstream of canonical validation, pricing,
risk, inventory, idempotency and order command authority.

### AI tools

Inventory every model-exposed tool/action. For each one prove schema validation,
actor/shop/permission/license authority, proposal approval where sensitive, exact
target/version revalidation, result correctness, idempotency, duplicate prevention,
timeout/cancel/retry, ambiguous external-effect handling, localized error/progress
states, privacy/redaction and bounded T470/floor resource/performance behavior.

Measure local dispatch/validation/business execution separately from model/network/
provider latency.

## Completion wave E — Phase 8 connected platform

**Objective:** complete remote work, hosted storefront, licensing/control and
zero-knowledge recovery without weakening desktop canonical authority.

Required outcomes:

- authenticated encrypted projection/command protocol;
- desktop-commit truth for remote success;
- shared multi-tenant Cloudflare control plane;
- hosted storefront with durable checkout receipt and atomic publish/rollback;

cannot decrypt seller backups.

## Definition of done

A phase/capability is complete only when its exit gate has objective evidence and every
known P0/P1 is closed. An exception may name unproven evidence, but an exception is
never described as “100% sure” or as a passed certification.

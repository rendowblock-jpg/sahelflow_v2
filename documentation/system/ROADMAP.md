This roadmap is the shortest safe path from the current application to a complete
SahelFlow 1.0 Founder AAA candidate and then to evidence-approved Stable. It
preserves dependency order while allowing each intensive session to advance
multiple phases through independent lanes.

The four-session overlay is tracked in issue #164 and governed by FD-027,
`WORKFLOW.md` and this document. It does not permit false completion claims or
bypass external Beta/Stable evidence.

## Sequencing rules

1. Shared authority is frozen before dependent behavior.
2. Preserve useful seller functionality and Founder data while replacing unsafe
   authority underneath.
3. Complete vertical seller journeys rather than accumulating disconnected
   pages.
4. One task/branch has one owner; parallelize only independent contracts/files.
5. UX, Arabic/RTL, accessibility, performance, security, migration, diagnostics
   and recovery travel with every phase.
6. Adapter presence is knowledge, not provider certification.
7. Connected systems remain optional to valid permanent local desktop work.
8. Ordinary feature PRs merge without app-version bumps; coherent merged
   milestones receive one unique signed Internal candidate.
9. At most one frozen signed candidate is in flight, but its publication,
   installation or Founder observation does not freeze independent work.
10. P0/P1 findings block the affected outcome; P2/P3 findings enter focused
    follow-up work instead of repeatedly reopening a green candidate.
11. Obsolete paths are removed only after migration, parity and recovery proof.
12. Beta and Stable remain explicit Founder promotions after their evidence gates.

## Phase 1 — Workspace/shop and business-integrity foundation

### Outcome

The local product operates through trusted workspace/shop context and one
transactional truth for order, delivery, inventory, COD money, return/refund,
audit and external effects.

### 1A — Workspace and shop authority

- introduce durable workspace identity compatible with the existing installation;
- bind every shop to one workspace;
- introduce persistent shop-incarnation identity;
- replace process-global/fallback selection with explicit trusted context;
- separate active UI preference from background/provider authority;
- switch shops without relaunch or cross-shop cache leakage;
- migrate existing registry/databases safely;
- make all-shop discovery, preflight, backup and migration journaled/resumable.

### 1B — Business state and movement contracts

- separate order/confirmation, delivery, inventory, COD/financial and
  return/refund state machines;
- create reservation and append-only inventory movement records;
- create COD receivable, remittance, fee, refund and correction movements;
- bind mutation, trusted audit, domain event, outbox, idempotency and exact
  compensation atomically;
- persist raw authenticated provider/inbound events before acknowledgement;
- enforce replay, checkpoint and reconciliation rules;
- migrate current behavior behind the new contracts with compatibility reads.

### Exit gate

- no operation silently uses another shop database;
- live shop switching works safely;
- replay/concurrency cannot duplicate stock, money, delivery or audit effects;
- cancellation, failure, physical return, remittance and refund have explicit
  movements;
- current Founder data migrates and rolls forward safely;
- automated, migration and installed milestone evidence passes.

## Phase 2 — Golden COD Journey

### Outcome

One seller can complete the full daily COD loop through real UI and data with
correct inventory, delivery, money, history and recovery.

```text
Catalog/import
→ customer/order intake
→ validation/risk
→ confirmation
→ stock reservation
→ shipment
→ delivery/failed/return
→ COD receivable/remittance
→ refund/exchange
→ inventory/finance/customer/analytics
→ restart/update/backup/restore preservation
```

### Work

- unify manual, WhatsApp, storefront and commerce intake behind one command;
- complete customer matching/duplicate and address/phone validation;
- make risk explainable and non-bypassing;
- complete confirmation, rejection and reservation behavior;
- complete shipment, mapping, tracking and exception states;
- distinguish delivered, COD collected and COD remitted;
- complete physical return inspection, disposition and refund/exchange;
- reconcile carrier statements, fees and discrepancies;
- derive dashboards/timelines from governed truth;
- complete every applicable loading, empty, permission, offline, stale, conflict,
  failure and recovery state;
- prove restart, update and backup/restore preservation.

### Exit gate

- journey passes through UI, API/domain, database and installed Windows;
- no route, provider callback or automation bypasses canonical rules;
- money/stock invariants hold under duplicate, interruption and retry;
- AR/FR/EN, RTL/LTR, keyboard and accessibility evidence passes;
- T470/floor-device budgets are measured and blocking regressions fixed;
- Founder accepts the coherent milestone candidate.

## Phase 6 — Shared connected platform

### Outcome

Optional remote work, hosted storefronts and encrypted recovery operate through
a bounded measured SahelFlow cloud while desktop remains canonical.

### Economics gate

Before public quotas:

- model Workers, D1, Queues, Durable Objects, R2, domains, media, egress,
  monitoring and support at 10/100/1,000/10,000 sellers;
- measure p50, p95, maximum and abuse scenarios per license;
- validate the five-year 7,000 DZD base reserve and 1,000 DZD extra-shop reserve;
- define quotas, limits, retention, alarms and service-exit behavior;
- retain shared multi-tenancy rather than default seller BYOC.

### Workstreams

- minimal identity/licensing/routing control plane;
- encrypted projection and signed remote-command relay;
- durable sequences, revocation, conflict and outage behavior;
- zero-knowledge backup keys, retention and recovery ceremonies;
- shared storefront releases, media, allocation and domains;
- durable checkout receipt, desktop import and reconciliation;
- operational PWA/browser companion;
- per-workspace metering, cost, quota and incident Founder views.

### Exit gate

- cloud outage cannot block permanent local work or corrupt desktop authority;
- remote success appears only after desktop commit;
- storefront success always has a durable receipt;
- neither SahelFlow nor Cloudflare alone can decrypt backups;
- tenant isolation, replay, revocation, restore and service-exit drills pass;
- real cost remains within approved continuity boundaries.

## Next route-level frontier — AI Agents

AI Agents is now the next product-workspace redesign. The existing server-side AI
action authority is protected and must be consumed, not rewritten.

Current reconnaissance establishes:

- `/agents` is a feature-gated shell around one large client `AiChat` component;
- session loading, streaming, tool events, proposal approval/recovery and most
  presentation state are mixed in one monolith;
- tool results are currently represented with raw/truncated JSON-like output;
- several UI/state failures are silently swallowed or shown as generic failures;
- consent/key/model/quota/degraded states are not first-class workspace states;
- some server/UI default strings remain hard-coded in French or inline locale maps;
- persisted proposal projection already exposes sanitized status, summary, expiry,
  execution state and error code;
- approval already requires trusted authority plus exact persisted proposal digest,
  and target/permission/license/shop state is revalidated server-side.

The redesign therefore should split state/transport from presentation, present
sessions + central assistant thread + contextual tool/proposal/action rail, render
typed tool-result cards and affected-record previews rather than raw JSON, make
pending/conflict/expired/failed/recovery state explicit, preserve history when AI
is unavailable, and move all AR/FR/EN copy under governed locale authority.

Settings follows AI Agents, then remaining production route adoption.

## 1. Yalidine (live-proven upstream)

**Base/auth:** `https://api.yalidine.app/v1`; headers `X-API-ID` + `X-API-TOKEN`; JSON.
**Rate limits:** 5 req/s, 50/min, 1000/h, 10000/day per account; quota headers `x-second-quota-left` / `x-minute-quota-left` / `x-hour-quota-left` / `x-day-quota-left`; exceeding → 429 + `Retry-After`; repeated violations extend the lockout. Parcel max weight 30 kg; bulk create ≤ 100.

**Create — `POST /parcels/`** — body is an **array** of parcels:
`order_id` (reference), `from_wilaya_name` (sender wilaya, default "Alger"), `firstname`/`familyname` (name split on whitespace; a single name is duplicated), `contact_phone`, `address`, `to_commune_name` (**name string, not a numeric id**), `to_wilaya_name`, `product_list`, `price` (COD, rounded), `do_insurance: false`, `declared_value` (rounded COD), `length/width/height: 1`, `weight` (default 1), `freeshipping: true`, `is_stopdesk`, `stopdesk_id` (required when stop desk), `has_exchange: false`.
**Response is an OBJECT KEYED BY order_id:** `{ "<order_id>": { success, tracking, label, message } }`.
**COD semantics (upstream merchant decision 2026-09-01):** the carrier collects product price **+ delivery fee** (`price 9000 + fee 600 → amount 9600`), pinned by upstream test.

**Update:** `PATCH /parcels/{tracking}` only while `En préparation`; response PII is masked — never write it back.
**Delete:** `DELETE /parcels/{tracking}` → `[{ tracking, deleted }]`; **HTTP 200 even on failure** — success only when `deleted === true`.
**Tracking:** `GET /histories/…` rows `{ date_status, status, reason, center_id, center_name, wilaya_id, commune_id }`.
**Stop desks:** `GET /centers/?page_size=1000&page=N`, auto-paginate while `has_more`, cap 10 pages; desk = `{ center_id, name, address, gps, commune_id, wilaya_id }`.
**Geo names:** `GET /wilayas/?page_size=1000` + `GET /communes/?page_size=1000&page=N` (cap 5 pages).

### 1.2 Webhook verification (upstream; research context — the desktop cannot receive webhooks)

GET CRC challenge → echo `crc_token` as plain text 200. POST: `X-Yalidine-Signature` (fallback `X_YALIDINE_SIGNATURE`); HMAC-SHA256 over the RAW body (UTF-8 key, no base64/prefix) → lowercase hex; 64-char header compared case-insensitively as hex, 44-char tolerated as base64; constant-time compare. Payload idempotency is **per `event_id`** (UNIQUE(provider, event_id)); duplicate detection walks the ORM error cause chain; always HTTP 200 with per-event results `ok|ignored|unmapped|error`; late failure events on terminal orders never increment attempts.

### 1.3 Commune name matching (solves ~25% of upstream dispatch failures)

`normalizeGeoName`: NFD → strip combining marks U+0300–U+036F → lowercase → remove spaces, hyphens, apostrophes (`'`, U+2019), periods. Match phases within the same wilaya bucket: exact → normalized equality → near-variant (length diff ≤ 1 AND shared 3-char prefix AND edit distance ≤ 1). Send the carrier's own matched spelling.

### 1.4 Egress block (upstream-only context)

Yalidine's Cloudflare zone 403-blocks all Cloudflare-Worker-originated traffic (verified upstream 2026-09-08, before auth). Upstream workarounds: allowlist request or a non-Cloudflare relay. **Not applicable to SahelFlow:** the desktop calls carriers from the installed machine.

## 2. ZR Express

**Base/auth:** `https://api.zrexpress.app`, prefix `/api/v1`; `X-Api-Key` + `X-Tenant` (do NOT use Bearer). 129 endpoints / 10 domains; UUID identifiers.
**Create:** (1) `POST /customers/individual` `{name, phone:{number1, number2?}}` → customer UUID; (2) territory resolve `POST /territories/search {keyword}` — **accent-sensitive upstream → always strip accents** ("Béchar" → 0 results); city = wilaya-level match (4 wilayas unserved: 33 Illizi, 37 Tindouf, 50 Bordj Badji Mokhtar, 56 Djanet); district = commune-level, **no fallback to items[0]**; (3) `POST /parcels` (single → UUID only; tracking arrives from `GET /parcels/{id}`) or `POST /parcels/bulk` ≤ 100 → `successes[{index, trackingNumber}]` / `failures[{index, errorCode, errorMessage}]`.
**Update:** parcel UUID required; separate PATCHes for amount/customer/address (address needs the FULL `{street, cityTerritoryId, districtTerritoryId}`; pickup-point parcels additionally require `hubId`); phone normalized to `+213…`.
**Delete:** `DELETE /parcels/bulk/by-tracking-number` (POST answers 405); 404/"not found" → idempotent success.
**Tracking:** `GET /parcels/{id}/state-history` accepts **only the UUID** — resolve via `GET /parcels/{trackingNumber}` first. Events `{newState:{name, description}, createdAt}`; state names are tenant-configurable free text (match `name`, fall back to `description`; accent/case-insensitive). `parcel.isReturn.updated` with `isReturn:true` is the only fully reliable terminal return signal.
**Labels:** `POST /parcels/labels/individual/pdf` → SAS URL expiring ~1h (re-resolve on demand).
**Stop desks:** hubs via `POST /hubs/search`; desks = `isPickupPoint:true`; wilaya mapped through territory addresses.
**Webhook:** API-driven registration `POST /webhooks/endpoints` + fetched secret `whsec_…`; **Svix verification**: `svix-id`/`svix-timestamp`/`svix-signature`, reject |now − ts| > 300 s, key = base64-decode(secret minus `whsec_`), signed content `"{id}.{ts}.{rawBody}"` HMAC-SHA256 → base64, multiple space-separated `v1,<b64>` signatures matched with ANY; idempotency key = `svix-id`.
**Default status mapping (accent-stripped, lowercase):** `livre|livre au client|encaisse|recouvert` → delivered; `retour_sous_traitant|colis_recupere|attente_recuperation_fournisseur|reinjecte_dans_stock|recupere_par_fournisseur|remboursement_reinjecte` → returned; `en_livraison|sortie_en_livraison` → out_for_delivery; `commande_recue|en_traitement|appel_confirmation|en_preparation` → preparing; `commande_confirmee` → confirmed; `pret_a_expedier` → ready; `confirme_au_bureau|confirme_chez_partenaire|dispatch|vers_wilaya` → assigned; `situation.created` events log only, never change status.

## 3. EcoTrack (≈82 couriers behind one API)

**Per-company endpoint** `https://{tenant}.ecotrack.dz` + `Authorization: Bearer {token}`; two exceptions use query-param auth (`/validate/token`, `/get/orders/status`). Rate limit 50 req/min → 429 `{"message":"Too Many Attempts."}`; reconcile capped ≤ 10 pages/run.
**Create:** `POST /api/v1/create/order` — **all params in the query string**: `nom_client, telephone (9–10 digits), adresse, commune (name), code_wilaya (1–58), montant (COD incl. delivery fees), type (1=Livraison…4=Recouvrement)`; optional `telephone_2, reference, code_postal (stop-desk station code), stop_desk, produit, remarque, weight, fragile, stock, boutique, gps_link`. Business failures return **HTTP 200** with `{success:false, error:10001|10002|10003}` (10001 locked, 10002 wilaya unserved, 10003 return not requestable); Laravel 422 bags are a third error style — all typed.
**Bulk:** `POST /api/v1/create/orders` ≤ 100, body **object-keyed by index string** `{"orders":{"0":{…}}}`.
**Lifecycle:** update `POST /api/v1/update/order?tracking=` (different param names; only pre-validation); validate `POST /api/v1/valid/order?tracking=&ask_collection=0|1` (locks); return request `POST /api/v1/ask/for/order/return?tracking=`; returns confirm `POST /api/v1/valid/returns {trackings:[…]}`.
**Tracking:** `GET /api/v1/get/tracking/info?tracking=` → `activity:[{date, time, status(key), station}]` (**not** `{data:[]}`); bulk `get/trackings/info` ≤ 100 with an unverified success shape — parse defensively and match to requested trackings only, never positionally.
**Status keys → normalized:** `en_livraison` → out_for_delivery; `livre_non_encaisse, encaisse_non_paye, paiements_prets, paye_et_archive` → delivered; `suspendu` → unreachable; `retour_chez_livreur, retour_transit_entrepot, retour_en_traitement, retour_recu, retour_archive` → returned; `annule` → cancelled; `prete_a_expedier, prete_a_preparer, en_preparation_stock, en_ramassage, vers_hub, en_hub, vers_wilaya, en_preparation` → dispatched. No webhooks — pull-only; manual validate (orders stay dispatched until `valid/order`).

## 5. Meta Pixel + Conversions API engine (upstream reference semantics)

**Trigger chain (upstream 4 modes):** storefront order create → `checkout` stage; dashboard confirmation → `confirmed` stage; delivered (or `out_for_delivery` for the long-haul wilaya set {1 Adrar, 8 Béchar, 11 Tamanrasset, 33 Illizi, 37 Tindouf, 44 Aïn Guezzam}) → `delivered` stage; carrier webhooks feed the same. Mode picks the event: `Lead` (checkout) / `Purchase` (checkout) / `Purchase_Confirmed` / `Purchase_Delivered`.
**Dedup:** server `event_id = orderId`; the browser pixel fires the same `eventID` on the thank-you page → Meta dedups (48 h window). `fbp`/`fbc`/IP/UA captured at placement.
**Hashing (SHA-256):** phone → strip non-digits, strip leading zeros, prefix `213` if absent, lowercase; names → NFD fold, strip marks, lowercase, letters only; city → letters only lowercase; postal → lowercase trimmed; country literal `dz`; `external_id` as-is; fbc/fbp/IP/UA raw.
**Claim uniqueness:** ledger row UNIQUE `(order_id, stage, event_name)`; insert-if-not-exists claim with a 10-minute in-flight lease; `sent` → skip; failure path records `failed`.
**Retry:** 5 attempts, 30 s exponential backoff; network/5xx retryable; 4xx → terminal failure record; malformed payload → non-retryable.
**Window:** 7-day attribution guard (`604800 s`) — expired → audited skip.
**Audit:** per attempt — status `sent|failed|skipped|claimed`, `meta_event_id` (fbtrace_id), error, sent_at.
**Test mode:** `test_event_code` attached only when enabled.
**Endpoint:** `POST https://graph.facebook.com/v26.0/{pixelId}/events`.
**SahelFlow porting note:** triggers must ride the desktop outbox with the same claim-lease semantics; CAPI failure never blocks order confirmation; the `Purchase_Delivered` signal comes from desktop order truth, not a projection.

## 6. Growth/checkout features (upstream reference semantics)

- **Landing pages:** per-product marketing page (`slug`, image stack, spacing), `views` counter, orders per page, revenue (product price only), CVR = orders/views (null when views = 0); sibling comparison per product instead of formal A/B experiments; duplicate = fresh draft with zeroed counters; images immutable + reference-counted deletes.
- **Image pipeline:** 8 MB cap, magic-byte sniff must equal claimed type, WebP transcode (quality 85) fail-open to original bytes, dimension probe fail-open to client-declared values, immutable cache control.
- **Abandoned cart:** per-session capture (name ≥ 2 chars + valid DZ mobile `^[567]\d{8}$` after 00213/213/0 stripping), 3 s debounce, `pagehide` sendBeacon, upsert per session; hourly sweep marks pending > 30 min as abandoned; convert is idempotent; recovery stats include estimated lost revenue.
- **Turnstile:** per-store config; missing/disabled → inert; missing token or in-band verification failure → fail-closed (`TURNSTILE_VERIFICATION_REQUIRED` / `TURNSTILE_TOKEN_INVALID`); transport failure → **fail-open** (revenue-first); `timeout-or-duplicate` → expired message; 10 s timeout.
- **WhatsApp OTP (dzverify):** `https://api.dzverify.com`, `X-API-Key`; send/verify + quota; anti-abuse 60 s per phone + 20/h per IP (fail-open on limiter errors); provider caps 5/recipient/hour, 200/account/hour; out-of-credits/5xx/network → fail-open with a 15-minute HMAC bypass token; rate-limit violations → no bypass; verified token's phone must equal the order phone.
- **Order-verified reviews:** one review per real order (unique per order), moderation `pending → approved|rejected`, storefront never exposes order UUIDs.
- **Quantity-tier offers:** trigger product/variant/quantity → reward product/variant/quantity or free shipping; highest trigger wins; reward stock checked; free-shipping zeroes the fee.

## 7. MCP agentic surface (EX-5 study)

> Study/design only — this section authorizes nothing. No external agent surface exists in SahelFlow and none ships without a separate explicit Founder decision. Read from `cod-server/src/mcp/**` at the `00f18fac…` pin, 2026-09-17.

**What CodFlow has (upstream truth).** A remote, stateless Streamable-HTTP MCP server (`POST /mcp`) in the `cod-server` Cloudflare Worker — `@modelcontextprotocol/server` v2.0.0 + Cloudflare `agents` v0.22.0 `createMcpHandler` + `@cloudflare/workers-oauth-provider` v0.10.3; a fresh `McpServer` per request (`legacy: "reject"` — no sessions/Durable Objects); no verified identity ⇒ **zero tools registered** (fail-closed).
- **Registry — 96 tools, verified:** `cod-server/src/mcp/registry.ts` holds `TOOL_REGISTRY: { requires, build }[]`; 98 `pick(...)` rows dedupe to 96 unique tools (listWilayas/listWilayaCommunes deliberately double-registered under two scopes); CI golden arrays pin the count and per-scope tool lists. Flat camelCase names, no prefixes (`listOrders`, `deleteCustomer`, `setShippingCommuneOverride`). Domains: customers 8, orders 8, landing pages 14, shipping profiles 10, stock 7, customer groups 7, customer tags 7, products 6, drivers 6, product groups 5, offers 5, variants 5, reviews 3, driver payments 3, wilayas 2.
- **Scope-gated visibility — hidden, not erroring:** `buildToolsForUser` skips any entry whose `requires` (AND-ed `domain:action` scopes, exact match or `*`) the caller lacks — enforced at **registration** time so the MCP client cannot even see tools it may not call. Admin role (or `*`) sees all 96. Grant-side: `computeGrantableScopes` caps a non-admin's consent choices at scopes they hold; the consent page renders per-domain checkbox chips (trilingual ar/fr/en, RTL-aware, CSRF double-submit); zero grantable scopes ⇒ "Nothing to authorize". No plan/tier gating.
- **Tool anatomy — two-layer validation + declared outputs:** layer 1 input is permissive (malformed LLM calls never crash the SDK), layer 2 is the strict Zod schema whose exact `.shape` merges into `TOOL_SCHEMAS` — *tools/list advertises what execute() validates; drift is test-impossible*. Every tool advertises an `outputSchema` from `toolOutput()`: a Zod union of `{success:true,…payload}` / `{success:false,error}` (loose payloads). Results are safe-parsed against the declared schema; on success both a JSON `text` block **and** `structuredContent` ship; on drift `structuredContent` is omitted but text still ships. Handled failures and thrown errors both surface as `isError:true` with the same envelope.
- **Destructive doctrine — annotate and trust the client:** `annotations.ts` **derives** `readOnlyHint/destructiveHint/idempotentHint/openWorldHint` from membership sets (read-only = read-scope-only tools + one override; destructive = the 23-entry `DANGEROUS_TOOLS`; idempotent = 4 membership tools; open-world = only `uploadLandingPageImage`); consistency is CI-proven. **The server executes destructive tools directly — there is no server-side confirmation round** (test-pinned). A server-side HITL was tried upstream and rolled back (it depended on client elicitation support; a fail-closed fallback would break destructive tools in incapable clients). Human agency lives at consent-time scope grants, client-side confirmation framed by annotations, and audit.
- **Audit & limits:** every invocation writes one `mcp.tool_called` activity row with `redactForAudit` (strings >1024 chars elided, depth ≤8); rate limit 200 calls/60 s per subject via KV fixed window, fail-open; pagination `limit`/`offset` (default 50, max 100–200) + `count`, orders additionally keyset-cursor; the only async pattern is image upload (job + poll, Workflow-driven, `openai/fileParams` `_meta` hints); no prompts/resources, no versioning/deprecation; `mcp.tool_declined` and the `elicit.ts` filename are stale vestiges of the rolled-back elicitation design.
- **Auth:** OAuth 2.1 provider (opaque tokens in KV, access 1 h, refresh 30 d), DCR + CIMD, RFC 9728/8414 discovery, dashboard-login relay via single-use HMAC tickets (5-min TTL, KV nonce replay check), `WORKER_SELF_URL` token-audience binding, instant revocation, management REST under session JWT or API key (`mcp:view`).

**What SahelFlow has (proposal-bound authority, already protected).** `AiActionProposal` (immutable authority snapshot; `proposalKey`/`proposalDigest` unique) → 1:1 `AiActionApproval` (decision + full approver snapshot) → 1:1 `AiActionExecution` (`executionKey` unique, `businessCommandId`); SQLite trigger guards pin the state machines (succeeded execution is terminal). Vocabulary in `src/lib/ai/actions/contracts.ts`: `read` (19) / `external_read` (2) / `sensitive` (8: `create_order`, `update_order_status`, `update_product_stock`, `cancel_order`, `create_product`, `update_product_price`, `create_customer`, `update_customer_notes`) / `blocked` (1: `assign_order_to_delivery` — registered, never advertised, never executable), `EXPECTED_AI_TOOL_NAMES` test-pinned. Creation requires a durable **person** actor with `ai.use` + `approvals.request` + the tool's permissions; args zod-validated and sealed with the shop business envelope key; 10-min TTL bound to the persisted chat message; `INSERT OR IGNORE` idempotency; keyed HMAC digests detect tampering. Approval is **digest-bound and person-only** (`approvals.approve` + `ai.use` + every permission the tool requires; approver locked to the first approver's identity snapshot); replay returns the stored encrypted result with `replayed:true` and rides `idempotencyKey: ai-action:${proposalId}` on the kernel's committed-command ledger. Execution mints an unforgeable branded authority, re-hashes args, and runs `executeBusinessCommand` (`ai.action.execute.v1`) — money truth, audit, domain events and compensations stay inside the kernel (`CANONICAL_CONFIRMATION_REQUIRED` holds; AI orders enter as `source:"ai_chat"` drafts). Remote-narrowing precedent: `getAllToolDefinitions` strips blocked tools and privacy-narrows `get_conversation_messages`.

**The mapping — composition, not port.** The two systems disagree on where the human gate lives: CodFlow's doctrine is *annotate-and-trust-client*; SahelFlow's is *server-side HITL* even for its own chat UI. The mapping therefore adopts CodFlow's **surface** conventions (registry shape, scope hiding, declared outputs, derived annotations) while every destructive verb rides SahelFlow's proposal-bound path — the proposal gate **replaces**, not supplements, client-side confirmation.
- **Class-by-class:** `read` (19) → direct execute, scope-hidden, rate-limited, audited (CodFlow's model verbatim). `external_read` (2) → same, with the privacy narrowing applied. `sensitive` (8) → the tool executes nothing and returns `{ pending_action_proposal: true, tool, proposal, proposalDigest }` — exactly today's chat-registry result shape; the MCP client cannot approve; the human approves in the dashboard Agents workspace with the digest. `blocked` (1) → never advertised (registration-time hiding makes this trivial).
- **Vocabulary crosswalk (verified both sides):** `create_order`↔`createOrder`, `update_order_status`↔`updateOrderStatus`+`recordOrderProductReturn`, `update_product_stock`↔`adjustProductStock`/`adjustVariantStock`, `create_product`↔`createNewProduct`, `update_product_price`↔(subset of) `updateProductDetails`, `create_customer`↔`createNewCustomer`, `update_customer_notes`↔(subset of) `updateCustomerProfile`, `cancel_order`↔*no CodFlow equivalent* (its `deleteOrder` is a destructive delete, not a lifecycle cancel — the divergence is correct for COD truth). The 19 read tools cover the same ground as CodFlow's list/get families. **What does not map:** CodFlow's delete verbs (`deleteCustomer`, `deleteProduct`, `deleteLandingPage`, …) — SahelFlow's AI vocabulary has no deletes, and adding one is a new policy entry + a Founder decision, not a default; driver settlements and shipping-profile overrides (SahelFlow's delivery authority model differs); plan gating (N/A).
- **Registry & scopes:** adopt the `TOOL_REGISTRY`-style entry list (`requires` + build) keyed on **SahelFlow's existing `Phase2Action` permissions** (resolved through `resolvePhase2Permissions`, deny-by-default) rather than minting a parallel `domain:action` OAuth vocabulary — one vocabulary, zero drift, owner role as the ceiling. Extending the vocabulary = one policy entry + executor case + target snapshot + test pin (already proven by the 8 sensitive verbs).
- **Outputs & annotations:** adopt `toolOutput()`'s success/failure union with per-tool `outputSchema` + `structuredContent` safe-parse-with-text-fallback, `limit`/`offset`+`count` pagination, 200/60 s fail-open rate limiting (local equivalent), and the **derived-annotations + golden-test** pattern (`destructiveHint` on the 8 sensitive verbs as UX framing only — the server gate is the actual human gate; mislabeling fails CI).
- **Transport & auth (the real fork):** SahelFlow is local-first; the natural shape is a **local sidecar endpoint** (stdio or localhost streamable HTTP) speaking to the trusted-actor model — not a public OAuth worker. The one genuinely missing component is the ingress that mints a durable `TrustedActorContext`/person actor for an external agent session; it must bind the agent to a non-person actor for *requests* while approval stays strictly person-held (`approvals.approve`), keeping an agent **never-approver**. CodFlow's OAuth/consent/revocation stack belongs to the hosted control plane and is **#230-gated** — it feeds EX-6, not this surface.

**Decision points recorded for the Founder (design input only).** (1) Transport: local sidecar endpoint (no #230 dependency, offline-first) vs control-plane-hosted (fully blocked until #230's owned-domain gate) — the study assumes sidecar if anything ships. (2) Vocabulary scope: the 8 sensitive verbs as-is, or extend (deletes, settlements) — extension is a new explicit decision per verb. (3) Scope vocabulary: reuse `Phase2Action` (recommended — single authority) vs new `mcp:*` scopes. (4) Confirmation doctrine: keep the server-side proposal gate as the *only* human gate; treat client confirmations as optional UX (recommended — CodFlow's rolled-back elicitation is the cautionary evidence). (5) Audit shape: per-invocation `via:"mcp"` audit rows with >1024-char redaction, riding the kernel's existing audit channel. No code, route, dependency or schema change is authorized or proposed; conversion requires the Founder's explicit agent-surface decision, and FRC-5's external gates are unaffected.

## 8. Control-plane deployment playbook (EX-6 research note feeding #230)

> Research only — **no deployment is proposed or performed**; #230's owned-hostname gate is unaffected. CodFlow practice read at the `00f18fac…` pin (three Workers in one account sharing D1+R2+KV: `cod-server` API, dashboard, storefront; docs/DEPLOYMENT.md + wrangler examples + worker sources). SahelFlow's side inventories `control-plane/{licensing,connected,backup,storefront}` as written-but-never-deployed source (every config is a `*.example` with placeholders; `wrangler` is not yet a dependency; `src-tauri/build.rs` refuses to package customer-online without owned-host authority).

**8.1 D1 migration wrapper (CodFlow contract).** Migrations live in `migrations_dir` declared on the `[[d1_databases]]` binding; application is `wrangler d1 migrations apply --local/--remote` with Wrangler's own `d1_migrations` ledger (checksums + ordering, no custom executor, no app-level ledger table). A thin shell wrapper (`scripts/d1.mjs`) injects the DB name (from root `.env`) into the right positional slot — Windows/`npx.cmd` rationale in its header. Hand-written later migrations are idempotent (`IF NOT EXISTS`) with documented preconditions in the header ("must return zero rows" checks); SQLite table rebuilds follow drizzle's 12-step `__new_` pattern inside `PRAGMA foreign_keys=OFF/ON`; **never rewrite an applied migration**. The critical gotcha: **migrate-remote before deploy, always** (skipping it produced 500s `field "alg" does not exist`), and deploy order `server → dashboard → storefront` because cross-worker URLs are circular until both exist. *SahelFlow application:* three of the four workers already ship `schema.sql` + ordered `migrations/*.sql` (backup 0001–0002, connected 0001, storefront 0001 — trigger recreations and trigger-guarded limits) and licensing self-checks schema shape via `sqlite_master` at startup plus a writability probe in `/healthz`; when #230 admits wrangler, add the `d1.mjs`-style wrapper + `db:migrate:local/remote` scripts per worker and adopt migrate-remote-before-deploy + precondition headers verbatim; do not retrofit a custom SQL executor over Wrangler's ledger.

**8.2 Rate limiting (two primitives, know which is which).** CodFlow's KV fixed-window counters (`mcp:rl:<subject>:<windowIndex>`, `expirationTtl = 2×window`, get-then-put accepted race) are **deliberately approximate and fail-open** — an absent binding or KV error lets the call through because the real security boundary is scope gating + audit; the same fail-open KV guards back the OTP cooldown (60 s per phone) and hourly IP cap (20/h). *SahelFlow's workers already use the stronger primitive:* Workers Rate Limiting bindings (`TRIAL_RATE_LIMITER` namespace 1001, simple 10/60 s; `CHECKOUT_RATE_LIMITER` 2001, 20/60 s) — keep those as the enforcement layer and reserve the KV fail-open pattern for cost-control bookkeeping only, mirroring the EX-4 slice-6 `otp-guards` contract already extracted into the desktop.

**8.3 OAuth-on-Workers (the pattern to have in hand — no SahelFlow worker exposes OAuth today).** `@cloudflare/workers-oauth-provider` wraps the whole Hono app as `defaultHandler` with the protected API as `apiHandler`; `authorizeEndpoint`/`tokenEndpoint`/`clientRegistrationEndpoint` + CIMD; RFC 9728 `resourceMetadata.scopes_supported = ALL_SCOPES`; access TTL 1 h / refresh 30 d; props (`{userId, role, scopes, …}`) encrypted by the provider into KV and read per request; **`WORKER_SELF_URL` binds the token `aud`** so a token minted for one worker/tenant is rejected elsewhere; consent = per-domain scope chips capped by `computeGrantableScopes` (never grant what the user doesn't hold). Cross-origin identity rides the **login-ticket relay**: `v1.<b64url(payload)>.<b64url(HMAC-SHA256(domain+payload))>`, domain separator `mcp-login-ticket.v1.`, 5-min TTL, ≥32-byte secret, single-use via KV nonce markers, CSRF double-submit `__Host-MCP_CSRF` (600 s, constant-time compare); fail-closed 503 when the ticket secret is missing/short. Revocation is provider-native and instant: `revokeGrant` deletes the grant **and every token under it**. Hourly cron runs janitorial `purgeExpiredData({batchSize:50})` alongside business sweeps. Secrets hygiene: real `wrangler.toml` is gitignored — commit `.example` templates only; secrets via `wrangler secret put` through temp-file stdin; placeholder-leak grep (`00000000-0000…`) must return no matches; secrets shared across two workers must be byte-identical (mismatch = 401s that look like bugs). *Feeds EX-5's control-plane option and any future external-agent surface; nothing to build until that decision.*

**8.4 R2 (SahelFlow's only bucket is zero-knowledge backup — no CORS needed).** CodFlow's image pipeline proves the browser-direct pattern: presigned PUT with folder allow-list (`clients must never control arbitrary key prefixes`), 10-min expiry, immutable `CacheControl: public, max-age=31536000`, magic-byte sniff vs claimed type, dimension probe fail-open, and the R2-SDK trap `requestChecksumCalculation/responseChecksumValidation: "WHEN_REQUIRED"` (R2 rejects default flexible-checksum headers on presigned PUTs); bucket CORS is provisioned by script (`PutBucketCorsCommand`) and **without it uploads fail silently**; async work rides Workflows with deterministic instance ids (`lpimg-<uuid>` / `capi-{orderId}-{stage}-{event}` = idempotency) and bytes never travel through workflow params (1 MiB cap). *SahelFlow divergence — deliberate and correct:* the backup worker mediates every R2 write server-side (`BACKUPS` holds ciphertext only, DEKs wrapped by the local per-license root key, no plaintext keys as Worker secrets), so no bucket CORS exists or should exist; if a future browser-direct surface is ever proposed, the CodFlow constraints above become binding. The magic-byte/immutable-cache/folder-allow-list contracts are already extracted in the desktop (EX-4 slice 4) — the same rules apply unchanged to any worker-side media path.
